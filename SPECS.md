# Entity Highlighter: Implementation Specs

Chrome extension (Manifest V3) that highlights named entities on any web page.
NLP runs on a Dockerized FastAPI service deployed to Render.

## 1. Goals and non-goals
**Goals**
- One-click highlighting of: PERSON, COUNTRY, LOCATION, INSTITUTION, GEOPOLITICAL, SECURITY, ACADEMIC, DATE, TIME, PHRASE.
- Same engines and colors as the Emacs tool (spaCy + NLTK + lexicons + regex).
- Self-hosted: the user owns the server and the API key.

**Non-goals (v1):** auto-run on every page, PDF viewer pages, shadow-DOM/iframe content, non-English text, user accounts.

## 2. Architecture
```
Popup (button) --activeTab--> content.js (injected on demand)
                                 | chrome.runtime.sendMessage
                                 v
                           background.js (service worker)
                                 | HTTPS POST /v1/extract + X-API-Key
                                 v
                  Render web service (Docker) -> FastAPI -> ner_core
                                 |                (spaCy NER, NLTK, lexicons, regex)
                                 v
                        spans per text node (UTF-16 offsets)
```
Only the service worker calls the API (avoids page CORS and mixed-content issues).

## 3. API contract
`GET /health` -> `{"status":"ok","model":"en_core_web_sm"}` (no auth; used by Render).

`POST /v1/extract`
- Headers: `Content-Type: application/json`, `X-API-Key: <key>` (required when `NER_API_KEY` is set).
- Request:
  ```json
  {"texts": ["On March 3rd, 2026 ..."],
   "options": {"nltk": true, "phrases": true, "labels": ["PERSON","DATE"]}}
  ```
  `labels` is optional (omit for all).
- Response:
  ```json
  {"results": [[{"start":3,"end":18,"label":"DATE","text":"March 3rd, 2026","source":"regex"}]],
   "meta": {"model":"en_core_web_sm","texts":1,"ms":42}}
  ```
  `results[i]` belongs to `texts[i]`. Spans never overlap. **Offsets are UTF-16 code units** (JavaScript string indices); the server converts from Python code points.
- Errors: 401 bad key, 413 over limits, 422 malformed body, 429 rate limit.
- Limits (env-configurable): 300 texts/request, 20,000 chars/text, 200,000 chars/request, 120 requests/min per client.

## 4. Entity model
Overlap resolution (lowest number wins; ties go to the longer span):
`SECURITY 0, GEOPOLITICAL 1, ACADEMIC 2, DATE/TIME 3, COUNTRY 4, INSTITUTION 5, PERSON 6, LOCATION 7, PHRASE 8`

| Label | Source | Color (light / dark) | Meaning |
|---|---|---|---|
| SECURITY | lexicon | #ffb3b3 / #8b1e1e | red: alarm |
| GEOPOLITICAL | lexicon, spaCy NORP | #d8c3f5 / #4b2e83 | purple: power |
| ACADEMIC | lexicon | #b2e8e0 / #12635a | teal: focus |
| DATE | regex, spaCy | #f8c8dc / #8a2c5e | pink: memory |
| TIME | regex, spaCy | #bdeefb / #0e6577 | cyan: precision |
| COUNTRY | spaCy/NLTK GPE + country list | #b6d4fb / #1d4e89 | blue: trust |
| INSTITUTION | spaCy ORG, NLTK ORGANIZATION | #c5cde0 / #2f3b5c | navy: formality |
| PERSON | spaCy, NLTK | #ffd6a5 / #9a5200 | orange: warmth |
| LOCATION | spaCy LOC/FAC/GPE, NLTK | #c7eab4 / #2f6b2f | green: place |
| PHRASE | NLTK noun chunks (2+ words) | #fff3b0 / #6b5d1a | yellow: gentle |

Lexicons live in `backend/ner_core.py` (`LEXICON`); extend and redeploy.

## 5. Backend
- Stack: Python 3.11, FastAPI, uvicorn (1 worker), spaCy 3.8 `en_core_web_sm`, NLTK 3.9, pycountry.
- spaCy loads once at startup with tagger/parser/lemmatizer disabled; calls are serialized by a lock and batched with `nlp.pipe`.
- NLTK data is baked into the image at build time (`NLTK_DATA=/opt/nltk_data`); no runtime downloads.
- Runs as a non-root user. Page text is never logged or stored.

| Env var | Default | Purpose |
|---|---|---|
| `NER_API_KEY` | generated by Render | Shared secret. Empty = open API (don't). |
| `SPACY_MODEL` | `en_core_web_sm` | Use `en_core_web_trf` for accuracy (needs more RAM; change the Dockerfile download too). |
| `ALLOWED_ORIGINS` | `*` | CORS origins. The extension's service worker does not need CORS. |
| `MAX_TEXTS`, `MAX_TEXT_CHARS`, `MAX_TOTAL_CHARS`, `RATE_LIMIT_PER_MIN` | see section 3 | Abuse limits. |

## 6. Docker and Render deployment
Local test:
```
cd backend
docker build -t ner-api .
docker run --rm -p 10000:10000 -e NER_API_KEY=devkey ner-api
curl localhost:10000/health
curl -X POST localhost:10000/v1/extract -H 'X-API-Key: devkey' \
  -H 'Content-Type: application/json' \
  -d '{"texts":["Dr. Amina Yusuf visited Berlin on 3 March 2026."]}'
```
Render:
1. Push this folder to a GitHub repo (`render.yaml` at the repo root).
2. Render dashboard: New > Blueprint > select the repo > Apply.
3. After the first build, open the service > Environment and copy `NER_API_KEY`.
4. Service URL looks like `https://ner-highlighter-api.onrender.com`.

Notes: the free plan sleeps after ~15 min idle (cold start 30-60 s) and has 512 MB RAM, which fits the `sm` model. Switch `plan: starter` in `render.yaml` for always-on.

## 7. Extension
**Manifest:** MV3; permissions `activeTab`, `scripting`, `storage`; `optional_host_permissions` for https and localhost, requested per API origin when the user saves settings. No always-on content scripts and no broad host access.

**Components**
- `popup`: Highlight, Clear, Settings; shows counts and errors.
- `options`: API URL, API key (stored in `storage.local`, not synced), NLTK toggle, Test connection.
- `background.js`: calls the API; 70 s timeout; one retry on timeout or network error (cold start); maps 401/413/429 to readable errors.
- `content.js` + `content.css`: DOM walking, batching, wrapping, legend.

**Highlight flow**
1. Popup injects CSS and script (idempotent) and sends `{cmd:"highlight"}`.
2. Collect visible text nodes (max 3,000). Skip script, style, input, textarea, select, iframe, svg, canvas, code, pre, contenteditable, existing marks, hidden elements, nodes under 3 chars or over 20,000 chars.
3. Batch (max 150 texts or 60,000 chars) and send sequentially.
4. For each node, verify it is still connected and unchanged, then split the text node and wrap each span in `<mark class="ner-hl ner-LABEL">`, applying spans in order.
5. Show a floating legend with counts; clicking a chip toggles that label via a class on `<html>`.

**Clear:** unwrap all `mark.ner-hl`, normalize text nodes, remove the legend and filters.

## 8. Security and privacy
- Visible text of the current page is sent to the configured server. Show this in the popup; do not use on banking, email or other sensitive pages.
- Input values and password fields are never read (inputs are skipped; only text nodes are collected).
- HTTPS is enforced for non-localhost servers. API key is checked in constant time.
- Legend and highlights are built with DOM APIs (no `innerHTML`), so page or API content cannot inject markup.
- Rate limiting and size caps protect the service from abuse.

## 9. Performance budgets
- Typical article (about 500 text nodes): target under 5 s warm, using the default `sm` model with the NLTK pass; disable the NLTK pass for speed.
- Cold start (free tier): under 70 s, handled by timeout plus retry.
- Memory: under 512 MB resident.

## 10. Acceptance tests
1. `sample.txt` text pasted into a page: every label appears, with the expected colors in light and dark mode.
2. Text with emoji before an entity highlights the correct characters (UTF-16 offset check).
3. Clear restores the original DOM text exactly.
4. Wrong API key shows "Invalid API key."; empty URL shows the setup message.
5. Re-running Highlight does not nest marks.
6. 4,000-node page is capped at 3,000 nodes without freezing the tab.

## 11. Known limitations and roadmap
- Entities are detected per text node, so a name split across tags (`Dr. <b>Yusuf</b>`) loses context.
- Highlights on pages that re-render the DOM (React, Vue) can be wiped; re-run to refresh.
- Roadmap: MutationObserver for dynamic pages, selection-only mode, per-site allow list, custom lexicons from options, multilingual models, icons.

## 12. Concurrency and redundancy (v1.1)
**Per server**
- `WEB_CONCURRENCY` worker processes (uvicorn supervisor respawns a dead worker; workers recycle after 1,000 requests). Each worker loads its own models (about 0.5-1 GB), so size it to RAM: 1 for 512 MB-4 GB hosts, 2+ for 2 GiB+ Cloud Run or larger.
- `MAX_INFLIGHT` (default 4) concurrent analyses per worker. Extra requests wait up to `QUEUE_WAIT_S` (8 s), then get `503` with `Retry-After`, which the extension treats as a signal to fail over.
- Models (spaCy and NLTK) are loaded at startup by a warm-up call, so the first user request never pays the load cost.
- NLTK tagger, tokenizer and parser are created once per process (previously per call).
- `ENABLE_NLTK=0` cuts memory and latency; the API then returns spaCy, lexicon and regex entities only.
- Rate limit is per worker (`RATE_LIMIT_PER_MIN`).

**Across servers (client-side failover)**
- Settings accept several API URLs, one per line. The extension tries the last good server first, then the others in order.
- Failover triggers: network error, timeout, 429, 5xx, 503. Pass 1 uses 30 s per server, pass 2 uses 70 s (cold starts).
- 401 (wrong key) and 413 (too large) are not retried. Use the same `NER_API_KEY` on every server.
- Suggested set: Render + Cloud Run (+ your phone or VPS at `http://127.0.0.1:8000` for offline use).
- "Test connection" reports every server separately.

**Supervision without Docker** (`backend/run_server.sh`): restart loop with exponential backoff (2 s to 60 s); exit code 137 is reported as killed by memory or the OS.

## 13. v1.2: selection mode, long texts, 10 concurrent users, scripts
**Selection mode (extension)**
- "Highlight selected text" analyzes only the selected ranges and is additive: existing highlights stay, the legend counts are recomputed from the page.
- Partial text nodes are analyzed as slices (`base` offset), so only the selected characters are highlighted. Text inside existing marks, code, inputs and hidden elements is skipped.
- "Analyze pasted text" in the popup renders highlights inside the popup (useful where the browser drops the selection when the popup opens, e.g. Firefox for Android).

**Long texts (server)**
- Limits: 300,000 chars per text, 600,000 per request (`MAX_TEXT_CHARS`, `MAX_TOTAL_CHARS`).
- Texts above `CHUNK_CHARS` (5,000) are split on paragraph, then sentence, then space boundaries; chunks tile the text exactly and offsets are shifted back, so spans are relative to the original text.
- Chunks run in batches of 16; the spaCy lock is released between batches, so a long text does not block other users.
- A per-request time budget (`MAX_REQUEST_S`, 120 s) returns 504 instead of hanging. The client adds 1 s of timeout per 10,000 characters.
- Rule-based passes (lexicon, regex) run on the whole text; the lexicon regexes are compiled once; overlap resolution is O(n log n).

**10 concurrent users**
- Defaults: `MAX_INFLIGHT=10` per worker, `QUEUE_WAIT_S=30`, `RATE_LIMIT_PER_MIN=600` per client IP per worker (users behind one NAT share an IP).
- Profile `team10` runs 2 workers with NLTK on (plan for 3 GB+ RAM). Cloud Run: `--memory 4Gi --cpu 2 --concurrency 10 --min-instances 1` and `WEB_CONCURRENCY=2`.
- Verify with `python loadtest.py --url URL --key KEY --users 10 --requests 5 --chars 20000` (also `--long 200000`). It exits non-zero on any error or if p95 exceeds `--p95-limit`.
- `GET /v1/stats` shows served, rejected, errors, inflight and RSS memory per worker.

**Scripts (`backend/`)**
- `setup.sh`: one-time install (apt packages, venv, dependencies, models).
- `server.sh start|stop|restart|reset|status|logs|run`: supervised background server with PID file, log rotation, orphan-worker cleanup, port check. `reset` stops everything, frees the port, optionally purges logs (`--purge-logs`) and starts clean.
- `.env.example`, `loadtest.py` (standard library only).
- `POST /admin/reset` clears one worker's rate-limit state and counters without a restart.
